## 修复 X 前端迁移击穿 client transaction id（get tweet 全站失败，✅ 已完成）

**背景**：`GET /api/tweet/get?id=2103358731920740663` 报
`OnDemandFileUrlResolutionError: Unable to resolve the X ondemand chunk URL from the homepage runtime`。
该错在 `FetcherService._getTransactionHeader → ClientTransaction.create` 阶段抛出，即**请求发出前**，
所有走 rettiwt-api 的 X 数据接口（guest 与 `TWEET_KEYS` auth 同）全部失败，重试/换 key 无效。

**先核实上游，再动手**（对齐 Space 卡片的探针范式）：

- X 把登出首页迁到新 **Rolldown/Vite**（"x-web"）外壳：`x.com/home`、`x.com/` 稳定返回新外壳
  （~17KB，`<script type="module" src="…/x-web/entry-client-logged-out-*.js">`，**无 `ondemand.s`**）
- `x-client-transaction-id@0.3.1`（npm 最新）靠正则从首页 HTML 解析 webpack chunk map
  （`NNN:"ondemand.s"`）反查 chunk 哈希；新外壳用内容哈希命名、**根本没有该 manifest 机制**
- 路由扫描（各 3 次）：`/i/topics`、`/i/display`、`/i/timeline`、`/i/communitynotes`、`/jobs`
  恒返回旧 webpack 外壳（~300KB，含 chunk map + `twitter-site-verification` meta + anim frames），
  而 `/home`、`/`、`/explore`、`/i/grok` 恒为新外壳
- 用**库自带正则**从旧外壳解出 `ondemand.s.6f1c1b85f72bd50ca.js`，拉取后 `INDICES_REGEX` 命中
  4 个索引 `[44,45,28,33]`；改从 `/i/topics` 取文档后，**真实 guest `TweetDetail` 请求成功**

**实现**（收敛在 vendored `FetcherService`）：

- `_handleXMigration` → `_fetchTransactionDocument`：遍历 `X_LEGACY_HOME_URLS`
  （`/i/topics` → `/i/display` → `/i/timeline` → `/i/communitynotes` → `/home`），
  返回第一个通过校验的文档；全部未命中则回退最后一个文档，让库抛出更具体的初始化错误
- 新增纯函数 `isUsableXDocument(document)`：`twitter-site-verification` meta + `ondemand.s`
  **双条件**（这正是 `ClientTransaction` 的两项输入）
- 原「迁移重定向/表单」逻辑抽到 `_fetchXHomePage(url)`，内部局部变量 `url` 改名 `formUrl` 避免遮蔽参数
- 新增 `ApiErrors.HOMEPAGE_FETCH_FAILED`（所有候选均网络失败时的兜底错误）

**踩坑 / 取舍**：

1. **别改上游库正则，改数据来源**：正则本身没错，是 X 不再产出它要的 input；修「从哪取文档」比修
   「怎么解析」更稳，也避免与上游分叉。
2. **不要只信「不再抛错」**：用真实 guest API 请求 E2E 复核（拿到含该推文 id 的 payload），
   对齐 postmortem #011「门禁先问『改坏它会不会红』」。
3. **明确降级而非静默兜底**：没有内置硬编码 indices/URL —— 若 X 把 legacy 路由也迁走，
   应再次明确报错（`OnDemandFileUrlResolutionError`）而非悄悄用可能过期的常量算出会被 403 的 header。
   兜底（缓存上次可用 URL / 健康探针）记入 postmortem #013 行动项待评估。

**验证**：新增 `test/unit/rettiwt-transaction-document.spec.ts`（旧/新外壳判定 + 列表非空，5 用例），
与 `smart-pool.spec.ts` 合计 13 passed；`bun run typecheck` 绿；改动文件属 `app/lib/rettiwt-api`
（eslint ignore），test 文件 lint 干净。真实上游 E2E 复核通过。

**文档**：[postmortem 013](../postmortem/013-upstream-frontend-drift.md) +「高频雷区」第 11 条 +
`CHANGELOG.md`。

## 真正根因：外壳请求缺 cookie（✅ 已完成，同日追加）

**背景**：owner 质疑「X 的重构是逐步的，`/i/topics` 只是还没轮到，库依赖的东西才是核心」——
顺着这个质疑复测，发现根因不在「换哪个页面」。

**决定性实测**（同一 URL `x.com/home`，仅切换 `Cookie`）：

| 请求              | 外壳           | `ondemand.s` |
| ----------------- | -------------- | ------------ |
| 匿名 `/home`      | 16.8 KB 新外壳 | ❌           |
| 带 cookie `/home` | 305 KB 旧外壳  | ✅           |

- 上游/此前的 `_handleXMigration()` 只发 `config.headers`，cookie 只在 `request()` 组装 API 请求时
  注入 → **外壳请求永远匿名**，即便配置了 API Key。
- 这是**回归**：Rettiwt #885 曾以「抓外壳时附 cookie」修好同一错误，被 #888 合并时丢失；
  上游 Lqm1 issue #20 亦归因为「需要有效登录 session」。
- 端到端：`TweetDetail` 与 `TweetLikers`（#908 的复现接口）均成功返回。

**实现**：新增纯函数 `buildXShellHeaders(headers, apiKey)`（存在 key 时附
`AuthService.decodeCookie(apiKey)`），`_fetchXHomePage` 改为使用它；候选列表改名 `X_SHELL_URLS`
并把 `/home` 提到首位（有 cookie 时首个即命中，legacy 路由降级为无 Key 时的 guest 兜底）。

**另**：实测 `ondemand.s` 的 key byte indices **每次构建随机**（30 个日更版本 30/30 不同），
故只可缓存 URL（内容哈希、不可变），不可 pin / 缓存 indices。

**验证**：`test/unit/rettiwt-transaction-document.spec.ts` 扩到 8 用例（含 cookie 头三项断言）；
真实上游 E2E 复核通过。详见 [postmortem 013](../postmortem/013-upstream-frontend-drift.md)
「后续修正」与 [transaction-id.md](../features/tweet/transaction-id.md)。

## AC 收口：外壳 cookie 回归防护（AC-TWEET-011，✅ 已完成）

**动机**：纯函数 `buildXShellHeaders` 的单测只能证明「这个函数对」，**发现不了「调用点不再用它」**——
而这正是本次 bug 的形态（上游 #885 修好、#888 合并时丢失的回归）。所以补一条**行为断言**：
mock `axios.get` 后跑真实 `_fetchTransactionDocument`，断言**实际发出的**外壳请求头 `cookie`
等于解码后的 cookie；无 `apiKey` 时保持匿名。

**落位**：`test/acceptance/ac-tweet.spec.ts`（`describe('AC-TWEET-011: …')`），与
`verify/acceptance-criteria/AC-tweet.md` v1.2 的 AC-TWEET-011 按 ac-contract 契约 1:1 绑定。

**Falsifiability 复核**：临时把 `_fetchXHomePage` 回退为 `this.config.headers` 后，该用例报
`expected undefined to be 'auth_token=…'`——确认它真能捕获本类回归，而非恒真（对齐 postmortem 011
「门禁先问『改坏它会不会红』」）。

**范围**：仅补验证与文档，运行时语义不变——PR #21 的 cookie 修复即最终实现。
