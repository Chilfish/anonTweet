# 2026-08-14

## 修复测试基线红灯（vitest 冷加载超时）— 文档先行（本 commit）

**背景**：AI Vision PR #14 评审（`docs/planning/ai-vision-review.md` §7.3）遗留的独立任务——`bun run test`
全量存在不稳定的失败集，已被接受为"基线红灯"，但**实际上挡着 pre-push gate 与 CI verify workflow 的
Unit tests 步骤**（lefthook `pre-push` 与 `.github/workflows/verify.yml` 均执行 `bun run test`，exit 非 0
即拦截）。评审要求"修复需改测试隔离层，独立 commit，不混入 PR #14"。

**问题形态（实测 3 轮）**：

| 轮次           | 结果              | 失败集                                                         |
| -------------- | ----------------- | -------------------------------------------------------------- |
| 1（pwsh 全量） | 110 pass / 5 fail | env.server ×2、api.tweet-get ×1、getTweet ×2                   |
| 2（pwsh 全量） | 111 pass / 4 fail | api.ai-translation ×3、api.tweet-get ×1                        |
| 单文件         | 全部通过          | env.server 单独 286ms 全绿；getTweet+api.tweet-get 同跑 2/3 过 |

→ **失败集每次漂移**，证明是资源竞争/超时问题而非逻辑 bug。

**根因诊断**：

1. 全部失败均为 `Error: Test timed out in 5000ms`，且都发生在**动态 `import('~/routes/api/...')` /
   `import('~/lib/env.server')`** 的冷加载路径（`api.ai-translation.spec.ts` / `api.tweet-get.spec.ts` /
   `env.server.spec.ts`）
2. 冷加载极慢：单文件跑 `api.tweet-get.spec.ts` 时 import 合计 **13.4s**（transform 4.8s + import 13.4s），
   超过其 per-test `15000` timeout；全量并行时 transform 56.9s / import 131.7s，14 文件并行竞争放大
3. 服务端路由模块依赖大图（routes → lib → providers → AI SDK → zustand），首个测试动态 import 即冷加载
4. 结论：**vitest 默认 `testTimeout: 5000` 对冷加载路径太短**，不是被测代码的问题

**修复方案（最小侵入，改测试隔离层）**：

- `vitest.config.ts`：`test.maxWorkers: 2`（16 核机器默认 worker 数 = CPU 核数，并行冷 transform 大依赖图
  导致单文件 4s 的冷加载在全量下 >30s；限到 2 个 worker，对齐 CI 4 核行为）+ 全局
  `testTimeout: 30_000` + `hookTimeout: 30_000`（兜底冷加载慢）
- 删除 `api.tweet-get.spec.ts`（2 处）/ `api.vision.spec.ts`（3 处）冗余 per-test `15000`（全局已接管，
  per-test 覆盖全局且偏短，是超时隐患源）
- 不重构测试逻辑：`vi.resetModules` 在 vitest 下受支持（dev-log 2026-08-13 记的 "Bun runner 不支持"
  是误诊断——那是 `bun test` 原生 runner 的行为；项目实际跑 `bun run test` = vitest）
- 踩坑：vitest 4 配置结构变化——`poolOptions.forks.maxForks` 已从类型中移除（旧文档键），
  正确写法是顶层/test 内 `maxWorkers`（本项目实测 `test.maxWorkers` 类型与运行时均接受）
