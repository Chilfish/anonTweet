## 修复 Vision Save 持久化失效（localCache 未开启 + DB 落库缺口）

**背景**：AI Vision（Phase 5）的「保存」流程实际不生效——刷新后 `visionInfo` 丢失。实测定位到两层问题：

1. **持久化通道整体被环境开关关闭**：`app/lib/localCache.ts` 的 `setLocalCache` 在
   `ENABLE_LOCAL_CACHE=false` 时静默 return，`.env` 里正是 `false`（`ENABLE_DB_CACHE` 同），
   且 `isDbAvailable()` 要求 `ENABLE_DB_CACHE=true`。结果 `handleSave` 的 `setLocalCache` 是
   no-op，服务端却照样返回 `{ success: true }`（假成功），客户端 `save` 还 fire-and-forget
   （`.catch(() => {})`），报错也被吞。
2. **读取链路**：刷新后 `/api/tweet/get` action → `getLocalTweet` → `getLocalCache`（禁用 →
   getter）→ `getDBTweet`（DB 禁用 → 直连 Twitter API）→ 全新推文无 `visionInfo`。Zustand
   里的 `updateTweet` 只是页面内存态。

**修复（A + B）**：

- `.env`：`ENABLE_LOCAL_CACHE = true`、`ENABLE_DB_CACHE = true`（本地缓存立即生效）
- `app/lib/service/getTweet.server.ts`：新增 `updateTweetVisionInfo(tweetId, visionInfo, baseTweet?)`
  ——**字段级合并**（对齐 `updateIGPostTranslation` 模式）：DB 有行则只把 `visionInfo` 合进
  `jsonContent`，避免客户端旧快照整体覆盖 DB；无行且有 baseTweet 时兜底整行插入；
  同时写 localCache。两层均 best-effort。
- `app/routes/api/ai/vision.ts`：`handleSave` / `handleGenerate` 改用 `updateTweetVisionInfo`
  （DB 落库，替代裸 `setLocalCache`），更新模块注释（移除「DB 落库留二期 TODO」）。
- `verify/acceptance-criteria/AC-vision.md` + `verify/modules/vision.verifier.ts`：新增
  AC-VISION-009（save/generate → localCache + DB 双层持久化，source scan 离线确定性）。

**验收**：`bun run verify/index.ts --module vision` 9 条 AC 全 PASS（AC-VISION-009 新增）。

**踩坑**：环境开关类 bug 的典型形态——`setLocalCache` 静默吞掉「未启用」状态并返回成功，
调用方无从感知。若后续再遇「保存了但刷新没了」，先查 `ENABLE_LOCAL_CACHE` / `ENABLE_DB_CACHE`。

## AIVisionBlock 可见性门控：默认不展示 + 逐推文开关 + 翻译按钮旁手动入口

**背景**：上一条「显示与开关解耦」让缓存的图片描述**无条件渲染**（commit `23a829b`）——
但对用户来说这是「推断内容」，默认铺在每条推文里反而打扰；尤其**截图时不想带上这次的
描述结果**。需求：全局「AI 图片描述」开关关着时，即使 DB/缓存里有结果也**默认不展示**；
想要时再展开。另在翻译按钮旁加一个手动添加图片描述的入口。

**Apple 设计取舍（对齐 HIG）**：

1. **克制默认（Conservative defaults）**：AI 描述 = 推断内容，Apple 从不自动铺开
   （Look Up 需显式手势）。→ 缓存内容展示与否 = `enableAIVision`（全局）∨ 逐推文覆盖。
2. **控制在内容现场（Contextual control）**：不把「每条推文要不要显示」做成全局设置；
   块头加文字级「隐藏」开关（与既有「仅译文/显示原文」同语言），逐推文会话级覆盖。
3. **渐进披露（Progressive disclosure）**：全局关 + 有缓存内容 → 折叠成一行
   「图片描述」细条（ℹ️ 模式），点按展开；截图上下文（chromeHidden）连细条都不渲染——
   WYSIWYG，截图尊重当前可见状态。
4. **单一入口（One primary entry）**：手动添加/编辑描述复用同一个视觉编辑器弹窗；
   仅当块内无任何入口（无内容 + 全局关）时，在翻译按钮旁显示图片描述按钮
   （打开弹窗 + 先置逐推文覆盖为展示，保存后新内容立即可见）。
5. **逐推文覆盖 = 会话级**：`visionVisibility` 存 translation store 但不进 persist
   `partialize`（与 `translationVisibility` / `tweetTranslationModes` 同哲学——per-tweet
   数据以服务端缓存为持久层）；plain 截图路由默认跟随全局开关，恰好满足
   「缓存了但全局关 → 截图里也没有」。

**决策链（纯函数 `resolveVisionBlockState`，下沉 `lib/vision/parse.ts`，Postmortem #002）**：

| 有内容 | 全局开 | 逐推文覆盖 | 交互模式              | 截图(chromeHidden) |
| ------ | ------ | ---------- | --------------------- | ------------------ |
| ✅     | —      | true       | content               | content            |
| ✅     | ✅     | —          | content               | content            |
| ✅     | ❌     | —          | **collapsed**（细条） | **hidden**         |
| ✅     | ✅     | false      | **collapsed**         | **hidden**         |
| ❌     | ✅     | —          | cta（生成入口）       | hidden             |
| ❌     | ❌     | —          | hidden                | hidden             |

**修改**：

- `app/lib/vision/parse.ts`：新增 `resolveVisionBlockState({ hasContent, enableAIVision, override, chromeHidden })` 纯函数
- `app/lib/stores/translation.ts`：新增 `visionVisibility: Record<tweetId, boolean>` + `setVisionVisibility`（不进 partialize，会话级）
- `app/lib/stores/hooks.ts`：新增 `useVisionVisibility(tweetId)`；`useTranslationActions` 补 `setVisionVisibility`
- `app/components/tweet/AIVisionBlock.tsx`：
  - 渲染改走 `resolveVisionBlockState`（不再无条件渲染缓存内容）
  - 头栏新增文字级「隐藏」（hasContent 时，逐推文覆盖 false → 折叠）
  - 新增折叠细条（全局关 + 有内容 + 交互模式，点按展开 = 覆盖 true）
  - `editor` prop：允许 TweetNode 上提的 `useVisionLogic` 复用同一弹窗（手动入口共用）
- `app/components/tweet/TweetNode.tsx`：`useVisionLogic` 上提到 TweetNode；翻译按钮旁新增
  图片描述入口按钮（有图 + 无内容 + 全局关 + 非截图时渲染），点击先置覆盖再开弹窗
- `app/components/settings/AIVisionSettings.tsx`：开关描述补「关闭时隐藏已缓存的描述」

## AI 图片描述防幻觉强化 + 上下文丰富注入（对齐翻译侧水准）

**背景（用户反馈）**：vision 的提示语与流程「过于简单脆弱」，不如 AI 翻译（`AITranslation.ts`）：
翻译侧有角色定义 / 保守命名协议（防幻觉）/ 术语表（HIGH）/ 作者档案 / 发布时间 / 引用上下文 /
实体参考；而 vision 的 describe/ocr 只是一句话 system prompt，`withContext` 只塞了裸 `tweet.text`，
术语表与本地词典完全没进链路。结果：模型对图中无法辨认的内容（人名/作品/品牌）、无文字图片、
知识库以外的名称会**瞎猜**；结果数量与图片数不符时还**静默错位**（`alignVisionIndexes` 数量不一致
原样返回 → UI 按图查找全 miss）。

**修改（5 层防线，对齐翻译 validate+retry 模式）**：

1. **反幻觉协议进 system prompt**（`app/lib/vision/prompts.ts`）：
   - describe：专有名词只有图中文字或上下文/术语表明确给出才写名称，否则视觉特征描述；
     看不清/模糊 → 明说，不脑补；纯色/空图如实描述；术语表优先
   - ocr：只提取图中可见文字，无文字输出空字符串，不把推文文字当图片文字
   - describe schema `description.trim().min(1)`：空/纯空白描述 = 幻觉性失败 → 触发重试
2. **上下文丰富注入**（`app/lib/vision/messages.ts` `buildVisionMessages`）：
   - `withContext` 开关控制「推文上下文」区块：作者 `@screen_name` / 发布时间 / 推文原文 /
     引用推文 / 实体参考（复用翻译侧 `generateEntityContext`，hashtag/mention/URL 是图中名称线索）
   - **官方 alt 文本**（`media_alt` 实体，`20000+i` → mediaDetails index；原作者的图片描述 =
     最强防幻觉锚点）与**术语表**（词典 + 自定义，`<Glossary>` HIGH 优先级）**不随 withContext
     开关**，始终注入——用户知识库常驻，防「仅看图片对知识库外内容瞎猜」
   - 所有区块首行明确「上下文仅供理解，不得当作图片内容」
3. **结果数量断言**（`app/lib/vision/parse.ts`）：新增 `VisionContentError` +
   `assertVisionResultCount(info, expected)`——模型跳过/合并图片、空数组时抛错，
   `describeImages.ts` 带反馈重试一次（`buildVisionRetryFeedback` 区分数量不符与 schema 失败），
   不再静默错位
4. **OCR 翻译步**（`app/lib/vision/translateOCR.ts`）：system prompt 加反幻觉协议
   （只翻译给出的原文、不确定片段保留原样、不用上下文/术语表替代原文）；解析失败带反馈重试一次
5. **术语表端到端透传**：`routes/api/ai/vision.ts` generate/translate schema 接受
   `translationGlossary`（max 4000）并透传；`use-vision-logic.ts` 生成/翻译请求合并
   `dictEntries() + translationGlossary`（与翻译侧同源同形态）

**产出**：`docs/planning/testing-infra-refactor.md`（审计报告 + 业界参考 + 目标架构 + Phase A~E
行动计划 + AC-TEST-001~008 验收标准）。核心决策：
