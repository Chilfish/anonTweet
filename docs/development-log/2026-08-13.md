## DeepSeek 策略切到 openai-compatible + 结构化 AI 错误 toast

**背景**：用户把 DeepSeek Base URL 指向 OpenCode Go 端点时踩了两个坑——(1) URL 少 `v1` 段返回 404；(2) API Key 无效时返回 401，但前端 toast 只显示"请求失败，请检查网络"，无从排查。两个问题合并处理。

**改动一：provider 迁移（`app/lib/providers/deepseek.ts`）**

- `@ai-sdk/deepseek` → `@ai-sdk/openai-compatible`（`createOpenAICompatible({ name: 'deepseek', baseURL, apiKey })`）。
- 动机：OpenCode Zen/Go 与 DeepSeek 官方均为 OpenAI 兼容协议；旧 SDK 的 `thinking: { type }` 字段在第三方兼容端点上语义不确定。
- 思考强度：`minimal → 缺省`（不传 reasoning_effort）、`low/medium/high → high`、`max → max`。
- 关键补丁：OpenAI 兼容协议没有标准思考 off 开关，用 `transformRequestBody` 在 `reasoning_effort` 缺失时补发 `thinking: { type: 'disabled' }`，保留"不开启思考"语义。
- 测试：`provider-base-url.spec.ts` mock 改为 openai-compatible；`provider-strategy.spec.ts` 更新 buildProviderOptions 期望；新增 transformRequestBody 注入用例。

**改动二：结构化 AI 错误 toast**

- 服务端：新增 `app/lib/ai-error.ts` 的 `normalizeAIError()`——用 `APICallError` / `AISDKError` 判别，把 `url` / `statusCode` / `responseBody` / `isRetryable` / 解析出的 `providerMessage` 归整为可序列化的 `AITransportError`。三条路由（`ai-translation.ts` 的 tweet+IG、`ai-test.ts`）catch 里统一返回 `aiError` 字段，并把 `catch (error: any)` 收敛为 `unknown`。
- 前端：新增 `app/lib/ai-error-toast.tsx` 的 `toastAIError()` + `app/components/translation/AIErrorDetail.tsx`。有 `aiError` 时渲染结构化详情（HTTP 状态徽章 / 错误类型 / 端点 URL / 响应体预览），超时放宽到 8s；无结构化信息时退化为普通消息。
- 组件约束：toast 的 description 渲染在 `<p>` 容器内，`AIErrorDetail` 只用 span/code phrasing 元素 + CSS block 排版，避免 div/pre 内嵌 `<p>` 造成非法 HTML。
- 消费者：`use-translation-editor-logic`、`use-alt-translation-logic`、`IGTranslateDialog`、`AITranslationSettings`（测试连接）。
- 附带发现：`fetcher.ts` 拦截器对 `body.status !== 200` 一律 reject，导致 `handleTestConnection` 的 else 分支（展示 `data.cause`）实际是死代码，失败都走 catch——因此错误详情统一在 catch 里取 `aiError`。
- 测试：新增 `test/ai-error.spec.ts`（构造真实 `APICallError` / `AISDKError` 验证归一化）。

**验收**：`typecheck` ✅ · `lint` 0 error ✅ · 变更相关单测 34 pass ✅。注：`bun test` 全量 4 fail 1 error 为 `env.server` / `getTweet` 的环境相关既有失败，与本改动无关。

**参数可配置性审计**：已写入 `docs/deepseek-ai-sdk.md`（provider 级 / 模型级 / callOptions 三级清单 + 暴露建议）。结论：维持暴露 `model / apiKey / baseURL / 思考强度` 即可；`temperature` 是唯一候选但翻译场景固定 0.5 更稳。
