## ins 翻译被中文检测误判（点按钮直接报错、无请求）

### 问题

手动点「AI 翻译」后控制台报 `[AI/browser] Translation failed … Translation returned empty`，且没有任何模型请求。根因是 `isChinese()` 只看 CJK 汉字比例：纯汉字日文（`本日発売` / `新曲公開` / `東京公演決定`）汉字占比 100%，被判为中文 → `translateIGCaption` 直接返回空串（`skipped: 'chinese'`）→ 调用方把「跳过」当成「空结果」抛出错误。请求自然一次都没发。

### 改动

- `translateIGCaption` 新增 `force`：显式触发时跳过中文自动检测（自动路径仍保留跳过）
- `isChinese` 增加假名短路：文本含平假名 / 片假名即判为日文（`東京公演決定です` 不再被当成中文）
- 透传 `force`：`requestIGTranslation`（浏览器直连）、`/api/ai-translation`（`type: 'ins'`）、`/api/ig/translate/:id`（显式接口缺省 `force = true`）
- 空结果的报错补上 provider/model（`Translation returned empty (deepseek/deepseek-flash)`），便于定位
- 新增 `AC-IG-011`：自动路径纯汉字日文返回空且不调用模型，`force` 时真实调用；含假名文本不被判为中文

### 验证

`bun run typecheck`、`bun run test`（667 passed）、改动文件 eslint；`AC-IG-011` + ac-contract 全绿。

## ins 单图占位高度修正

### 问题

单图帖子的媒体容器没有固定高度：高度取决于 `<img>` 的固有尺寸。图片未就绪（懒加载 / CDN 未返回）或加载失败时，`<img>` 只剩约一行文字高度，`MediaLoading` / `MediaFallback` 便渲染成一条细灰带（用户截到的那张），图片回来后整张卡再突然撑高。

### 改动

- `IGMediaGrid` 新增 `getMediaAspectRatio()`：`width` / `height` 优先，缺失时回退 `width_original` / `height_original`
- 单图分支（`SingleMedia`）用 `aspect-ratio` 锁定容器高度，图片 / 视频用 `size-full` 填满；加载骨架与失败占位都按真实比例占位，多图网格（`aspect-square`）不受影响
- 新增 `AC-IG-010`（`test/acceptance/ac-ig.spec.ts`）：单图渲染断言 `aspect-ratio:0.75` + 骨架存在，多图断言不套用该比例

### 验证

`bun run typecheck`、`bunx vitest run --project acceptance test/acceptance/ac-ig.spec.ts test/acceptance/ac-contract.spec.ts`；用 agent-browser 阻断图片请求复现：修复前媒体区高 20px，修复后按 1440×1920 占位 797px。
