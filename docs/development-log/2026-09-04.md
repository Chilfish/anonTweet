# 2026-09-04

## 媒体图片链接统一为 /slug.jpg（去掉 ?name=&format= 查询参数）

按需求把媒体图片链接从 twimg query 形态 `?name=<size>&format=<ext>` 统一改为路径
形态 `<slug>.<ext>`（如 `.../HPxZhM0aQAAZxz3?format=jpg&name=small` →
`.../HPxZhM0aQAAZxz3.jpg`），与官方原始图 URL 形态一致。

**新增/改动**：

- `app/lib/media-url.ts`（新）：`normalizeMediaUrl` —— 唯一归一化入口：
  路径已带图片扩展名原样保留，否则把 `format` 并入路径；仅清理 `format`/`name`
  两个查询参数，其余参数（如 `foo=bar`）保留；空串/非法 URL 原样返回。
  所有媒体链接消费方共用，避免第六套 URL 逻辑（Postmortem #005）。
- `getMediaUrl`（react-tweet/utils）：去掉 `size` 参数，改为
  `proxyMedia(normalizeMediaUrl(...))`；`tweet-media` / `tweet-media-video` 调用点同步更新。
- `buildMediaUrl` / `fetchMediaImages`（vision/fetchImage）：同款归一化，去掉
  `MediaSize` 与 `size` 参数（原「默认 small 缩略图」DR-5 取舍随 query 形态一并移除，
  一律取原始图；代价是 AI 视觉输入体积变大，Gemini/OpenRouter 自动降采样兜底）。
- 卡片图片：`TweetCard`（CardImage）/ `TrendingCard`（主图）渲染前先归一化再走代理，
  覆盖 API 返回即带 `?format=png&name=orig` 的 card_img / jetfuel 图片来源。
- Markdown 导出：`generateMediaMarkdown` 的图片链接同样归一化（导出与界面一致）。
- 测试：`test/unit/media-url.spec.ts`（新，8 用例）+ `vision.spec.ts` buildMediaUrl
  用例重写为归一化断言。

**收益**：媒体 URL 形态统一且以图片后缀结尾 —— `/api/proxy/image` 白名单
`IMAGE_EXT_RE` 的后缀匹配缺口（见 verify/log.md）对 Tweet 媒体不再构成障碍
（仍有 IG 域名白名单路径不受影响）。

**验证**：`bun run typecheck && bun run lint && bun run test` 全绿。
