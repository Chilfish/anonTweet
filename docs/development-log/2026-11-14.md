# 开发日志 2026-11-14

## 无图 link card 回退占位块 + 域名取 `vanity_url`

### 问题

推文 [1995332387627291098](https://twitter.com/nonoka_yumemita/status/1995332387627291098)（youtu.be 音乐链接）的卡片渲染与 X 官方不一致：

1. 我们的卡片塌成**纯文字卡**（只有域名 / 标题 / 描述），官方是**左侧图标占位块 + 右侧详情**。
2. 域名显示 `www.youtube.com`，官方显示 `youtube.com`。

### 上游取证

`TweetResultByRestId` 与官方 `cdn.syndication.twimg.com/tweet-result` 返回的 `card` 完全一致：

- `name: summary_large_image`
- `binding_values` 只有 App-Store 那一套：`app_name: YouTube`、`app_star_rating`、`app_id`、`app_price_amount`、`vanity_url`、`domain`、`title`、`description`、`card_url`
- **没有任何** `thumbnail_image_*` / `photo_image_full_size_*` / `summary_photo_image_*` binding

对照组（同一条 youtu.be 链接的其他推文、nicovideo 卡）均带完整图片 binding，说明这是上游该卡本身缺图，不是解析丢字段。也验证了 `responsive_web_enhance_cards_enabled: true/false` 对结果无影响（两种情况 binding 完全相同）。

结论：**缺图是上游事实**，X 前端对此的回退就是占位 icon；我们的偏差在于「无图即纯文字卡」这一布局选择。

### 改动

- `app/lib/react-tweet/utils/parseTweet.ts`：`mapTwitterCard` 的 `domain` 改为优先取 `vanity_url`、回退 `domain`（`vanity_url` 即官方卡片展示的域名，`domain` 常带 `www.` 前缀）。
- `app/components/tweet/TweetCard.tsx`：新增 `CardImagePlaceholder`；`card.type === 'summary_large_image'` 且无 `imageUrl` 时渲染占位块 + 右侧详情（与官方一致），`summary` 纯文字卡与有图大图卡行为不变。
- 新增 fixture `test/fixtures/cards/no-image-app-card.json`（真实推文 card 原样裁剪）。
- AC：`verify/acceptance-criteria/AC-card.md` 新增 AC-CARD-015（域名优先级）/ AC-CARD-016（无图大图卡占位渲染），总计 16 条。
- 测试：`test/unit/parseTweet.spec.ts`（AC-CARD-015 ×2）、`test/acceptance/card-render.spec.ts`（AC-CARD-016 ×2）。
