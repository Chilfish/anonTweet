## 推文搜索接入（feat/tweet-search）

按 docs-first 启动 Twitter/X 推文搜索：`/search` 页面 + BFF `/api/tweet/search`（返回
`EnrichedTweet[]`，格式同 `/api/tweet/get`，先不做分页）+ rettiwt-api 授权补缺。

**现状盘点**：rettiwt-api 底层搜索链路（`TweetRequests.search` / `TweetService.search` /
`Extractors.TWEET_SEARCH` / `Requests.TWEET_SEARCH` / `FetchResourcesGroup`）已完整，缺口在：

1. `AllowGuestAuthenticationGroup` 缺 `TWEET_SEARCH`（guest 池直接 `RESOURCE_NOT_ALLOWED`）
2. App 数据层无搜索 fetch/解析函数
3. 无 BFF 路由 / `/search` 页面 / footer 入口

**计划**：

- 方案文档 `docs/features/tweet/search.md`（含接口约定与 5 阶段计划）
- AC 先行：`verify/acceptance-criteria/AC-tweet.md` v1.1 新增 AC-TWEET-009（离线解析回归）
  / AC-TWEET-010（集成端点返回推文列表）
- 数据层 `parseSearchTimeline` 纯函数（对齐 `fetchListTweets` 解析范式，规避 postmortem #001）
  + `fetchSearchTweets`（`twitterPool.run` + `ResourceType.TWEET_SEARCH`）
- 校验 `app/lib/validations/search.ts`、路由 `app/routes/api/tweet/search.ts`、页面
  `app/routes/search.tsx`、footer 内链入口

**约定**：搜索端点只返回推文列表（`EnrichedTweet[]`），与 `/api/tweet/get` 同构；
分页（cursor）留待后续迭代，本期不暴露。
