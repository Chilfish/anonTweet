## Tweet GET 全部入口统一走缓存链（getLocalTweet）

**背景**：`app/routes/api/tweet/get.ts` 的 GET loader 与 `app/routes/tweet.tsx` 的 SSR loader
此前调用 `getTweets(tweetId)`（默认 getter `getEnrichedTweet`）——直连 Twitter API，
**不读不写任何缓存层**：每次 SSR 渲染 / GET 都重复烧 API 配额（SmartPool key 限流风险），
且拉取结果永不落盘，重读（新开页面 / 爬虫 / 截图）仍打 API。POST action 早就走
`getLocalTweet`（localCache → DB → API，本地层 fire-and-forget 异步写），两处不一致。

**改动**（2 文件 + 测试）：

- `app/routes/api/tweet/get.ts` loader：`getTweets(tweetId)` → `getTweets(tweetId, getLocalTweet)`
- `app/routes/tweet.tsx` SSR loader：同样改为传 `getLocalTweet`（新增 `getTweet.server` import）
- 测试：`test/unit/api.tweet-get.spec.ts` 锁「入口经缓存链」（loader 传 `getLocalTweet` +
  tweet.tsx 源码扫描），防回退成裸 `getEnrichedTweet`

**为什么安全**：`getLocalTweet` → `getLocalCache`(ENABLE_LOCAL_CACHE 关 → getter 直通) →
`getDBTweet`(DB 关 → `getEnrichedTweet` 短路)。两开关默认 false 时行为与改动前完全一致；
开启时「接口完成后」由缓存层隐式持久化，路由无需主动调 `setLocalCache`。

**重读/并发说明**（对齐「注意重读调用」）：`getTweets` 对 quoted/parent 的反复 getter 调用
均走 `getLocalCache` 的 `pendingRequests` 请求合并 + 按**单条 tweetId 独立落键**
（不把整条链合并存到主 id 下，重读 parent/quoted 各自命中自己的键），
并发同 id 请求去重为一次上游获取，不存在快照互相覆盖。

## 用户时间线接口加 ENABLE_TIMELINE 开关（✅ 已完成，2026-08-31）

自部署用户无法自行启用。按 `ENABLE_BILI` 同款模式改为环境开关控制：

- **`app/lib/env.server.ts`**：新增 `ENABLE_TIMELINE`（`z.stringbool().default(false)`，**默认关闭**）
- **`app/routes/api/user/timeline.ts`**：`!env.ENABLE_TIMELINE` → 固定 429（message 提示开关用法）；
  开启后恢复真实实现（`getDBUser(username)` → `getEnrichedUserTweet(user.id)`，DB 缓存 → API），
  `catch (error: unknown)` + `instanceof Error` 收窄（合规），顺带修正 `./+types/get` → `./+types/timeline`
- **部署说明**：公共环境（Vercel）实际已设 `ENABLE_TIMELINE=true`，接口按**正常接口**对外；
  AI 面向文档（SKILL.md、llms.txt/OpenAPI、AC-LLMS）不提及开关，统一文档化为
  「用户时间线 → 200 EnrichedTweet 数组 + 429/500 错误」
- **人工文档**（README `.env` 示例、`docs/INDEX.md` 默认关闭标注、`project-architecture.md` §2.4）

- **测试**：`env.server.spec.ts` 补默认 false / 显式 true 解析；`llms.spec.ts` 429 断言改为
  正常接口语义（200 EnrichedTweet 数组 $ref + 429/500）
