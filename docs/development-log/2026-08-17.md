## 修复「句首补充」显示与持久化链路（index 对齐合并丢实体）

**背景（用户反馈）**：翻译编辑器（`TranslationEditor`）的「句首补充」（prepend，`index: -1`
实体）坏了两层：

1. **显示层**：在编辑器里填的句首补充，保存后页面上不显示——合并时被丢弃；
2. **持久化层**：刷新后句首补充丢失。用户贴出 `/api/tweet/set` 的 payload，确认句首补充
   实体根本没进同步数据，且 `aiTranslation` 上挂着用户手动加的句首文本「听说在 」，状态很怪。

**根因（两处 index 对齐合并 + 一处 AI 流丢片段 + 一处持久化触发缺口）**：

1. **`mergeTranslationsToField` / `mergeEntityTranslationsByIndex`（`lib/translation/resolveEntities.ts`）**
   ——显示与 materialize 共用，只 `base.map()` 按 index 对齐合并，**base 里不存在的 index
   （句首补充 `-1`）被静默丢弃**。这是 `20a1103`（引入 resolveTranslationView 统一合并逻辑）
   重构时的回归：`9cec987` 最初实现是直接 `unshift` 到数组的。
2. **`mergeTranslationEntities`（`lib/service/getTweet.server.ts`）**——服务端读取 DB
   `tweetEntities` 缓存时同样只按 index 覆盖 + 无条件 push media_alt，句首补充实体被丢。
   即使截图同步把 `index: -1` 写进了 DB，刷新读取时也恢复不出来。
3. **`applyAITranslations`（`lib/react-tweet/utils/entitytParser.ts`）**——AI 把占位符移到
   句中时（如 `听说在 <<__HASHTAG_0__>> 里出现了…`），`restoreEntities` 会把译文拆成
   多个片段（多余的片段 index 为 30000+），而 `applyAITranslations` 只按 base 对齐合并、
   **把 30000+ 的片段静默丢掉**——这就是 payload 里 `aiTranslation: "听说在 "` 的来历
   （AI 译文只剩第一段，后半段丢失）。
4. **持久化触发缺口**：手动翻译（含句首补充）只在**截图**时才 `syncTranslationData` 到
   服务端（DB `tweetEntities`），保存按钮只写内存 store（store persist 的 `partialize`
   也不含 translations）→ 不截图必然刷新即丢。

**修复（5 处代码 + 测试）**：

| 文件                                                                         | 修改                                                                                                                                           |
| ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `app/lib/translation/resolveEntities.ts`                                     | `mergeTranslationsToField` 保留 base 外的额外实体：句首补充（index < 0）插入最前，其余按 index 追加末尾；无翻译内容的裸实体仍过滤              |
| `app/lib/markdown.ts`                                                        | `generateTextFromEntities` 仅在原文（`useTranslation: false`）跳过 index < 0，译文导出包含句首补充                                             |
| `app/lib/service/getTweet.server.ts`                                         | `mergeTranslationEntities` 同样保留 index < 0 实体插最前；media_alt 不再重复追加（base 已含时只覆盖 translation）                              |
| `app/lib/react-tweet/utils/entitytParser.ts`                                 | `applyAITranslations` 遇到与 base 结构不对齐的 AI 翻译流时直接返回完整流，不再丢片段（与显示层 `shouldRenderTranslatedEntitiesDirectly` 一致） |
| `app/routes/api/tweet/set.ts`                                                | `/api/tweet/set` 写 DB 后同步刷新 localCache（`mergeTranslationEntities` + `setLocalCache`），避免同步后 1h TTL 内刷新仍读到旧缓存             |
| `app/hooks/use-translation-editor-logic.ts` / `use-alt-translation-logic.ts` | 保存时调用 `syncTranslationData` 持久化到服务端（DB + localCache），刷新后恢复手动翻译与句首补充                                               |

**测试**：`resolveEntities.spec` / `resolveTranslationView.spec` / `translationMaterialize.spec` /
`markdown.spec`（新增）/ `getTweet.server.spec` / `entitytParser.spec` 补用例，覆盖：
合并保留句首补充、仅句首补充时 shouldShow、materialize 首位、markdown 原文不含/译文含、
服务端 merge 恢复句首补充且 media_alt 不重复、AI 流不丢片段。
