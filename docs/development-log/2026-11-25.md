## CI verify 失败：dev server 被换成 Bun 运行时

**现象**：`Verification Suite` 红在 `TestServer failed to become ready`，其上方真实错误是
miniflare 的 `undici.fetch` 去连 `http://localhost/__vite_plugin_cloudflare_get_export_types__`
被拒（`ConnectionRefused`），dev server 启动 1.5s 后退出。

**根因**：`68a39d9` 把 `bun run dev` 改成 `bun scripts/dev.ts`，devkit 的
`resolveServerSpawn({ runtime: 'bun' })` 让 dev server 从 Node（旧链路是 `.bin/react-router`
的 node shebang）换到了 Bun。`@cloudflare/vite-plugin` 的 miniflare 用 undici 的
Dispatcher 做进程内转发，Bun 的 `undici` 只是残缺 shim（`MockAgent.disableNetConnect`
都没有），dispatcher 被忽略 → 真实网络请求 → `localhost:80` 拒绝。
探针验证：`node` 下 `undici.fetch(..., { dispatcher: mockPool })` 命中拦截，`bun` 下直接抛
`disableNetConnect is not a function`。

**处置**：`scripts/dev.ts` 改 `runtime: 'node'` + 注释；干净端口上跑
`bun run verify/index.ts --ac AC-DEV-001 --exit-on-fail` 通过（dev 正常起在 9081）。
清掉了历史残留的两个 dev server 进程（9080/58574/9230 端口）。
新增 `docs/postmortem/017-dev-server-runtime-mismatch.md`（SEV-2 / Mitigated），
README 索引与 `AC-PM-001` 的 `REPORT_IDS` 同步到 017。

**教训**：包装脚本改变运行时属于隐性破坏；同类问题只在 CI 暴露时，先怀疑「本地跑的是不是同一个运行时」。

## 推文多图媒体：>4 张改横向轮播

**背景**：X 单条推文支持最多 20 张图片，旧渲染只有按数量硬编码的网格
（`grid-cols-2` + `length > 4 && 'grid-rows-2'`），每格仍用 16:9 的 padding 撑高，
20 张就变成 10 行的长图，比例和阅读节奏都崩了。数据层没有 4 张上限，问题全在渲染分档。

**方案**（所有者裁决：>4 张切轮播、露边形态；截图不改变布局）：

- 阈值 4：1/2/3/4 张保留官方经典网格，5 张起横向 scroll-snap 轮播；
- 露边：每页 `basis-[60%]`（中间一张 + 左右各露 20%，按官方 `cache/mutil-images.html`
  实测的 `padding-bottom: 79.84%` + `aspect-ratio: 0.75` 反推），轨道 `gap-1`，
  右上角计数胶囊 `1 / 20`（20 个圆点不可读）；
- 比例：每页按**各自**原比例，高度封顶 `min(640px, 80vh)`，页宽 = 比例 × 最大高度
  （720×2400 → 0.3 → 192px 宽，竖向长图完整显示为窄条；超宽图按基准宽显示），
  轨道 `items-start`，病态比例夹在 0.1–4；
- 引用推文同样轮播但不出箭头；竖向模式（`isInlineMedia`）维持全宽堆叠；
- 截图态不再强制平铺：plain 路由与常态复用同一套渲染，保留全部元素；
- 抽取 `app/components/ui/media-carousel.tsx`（轨道 + 箭头 + 计数/圆点 + sr-only 计数），
  `CarouselCard` 广告卡轮播改用它（整页 + 圆点不变），删掉自带的重复实现。
