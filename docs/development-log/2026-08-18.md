**实测**（临时脚本 monkey-patch `Requests.TWEET_DETAILS` 后用 `FetcherService` 直连）：

`jetfuel_attachment.payload` 为 base64 的 X 私有二进制（类 protobuf，长度前缀，
无公开 schema），内含可读字符串：`trending-card`、目标 URL、图
`HPxZhM0aQAAZxz3.jpg`（官方 HTML 同图）、`Entertainment` / `Celebrity` 分类、
标题、3 个头像 URL、`16.5k posts`、另一段描述（官方 HTML 同文）——即官方卡片

（`TweetRequests.details`），换 queryId + 对齐官方 features 即取到全量数据**；
payload 解析需按长度前缀提取字符串。改造列入 backlog（阶段二待办），
fixture 存档 `tmp/raw-tweet-2089577916694942006-jetfuel.json`（本次仅完成统一卡片

### 补充研究（用户提供 emusks 库，2026-08-19）：jetfuel wire format 解码参考

用户提供逆仓库 `emusks`（radicle）的 `src/parsers/jetfuel.js`（已存
`C:\Users\13154\Desktop\tmp\jetfuel.js`）与文档 `docs/src/jetfuel/`。研究结论：

- **格式确认**：payload 是 X 私有「节点化字典压缩帧」——`<len:u8> <utf8 string>` 内联
  字符串 + `0x11` 节点 intro（后随 `[typeString, keyString]`）+ `02 <field> 00 00 00 <hash:u32>`
  atom 引用（FarmHash 全局样式字典）+ `03` 引用列表。**atom 字典在懒加载 chunk 里，
  无公开 schema**，官方文档明确 "Treat the output as inspectable structure, not a stable schema"；
- **无 trending-card 专用解析**：`decodeJetfuel` 只是通用结构扫描（strings/nodes/atoms/
  lists/timelineTokens），且 `looksLikeString` 仅认 ASCII（0x20-0x7E 且有字母），
  **日文标题/描述会被截断**（实测本 payload 只吐 ASCII 片段）→ 不能直接复用，
  需自写「按长度前缀 + 可读性（含 CJK）提取字符串」的轻量解析；
- **附带发现**：库暴露官方服务 `ogImageUrl(tweetId)` =
  `https://jf.x.com/images/post/<id>`（1200x630 OG 分享图）与
  `mediaPreviewUrl(tweetId)` = `https://jf.x.com/images/media-preview/<id>`，
  可作为推文 OG 图/媒体预览的补充来源（无 auth 可拉）。

→ 改造方案维持 backlog 待办：请求参数对齐（取 jetfuel data）+ 自写 payload
字符串提取器（fixture 驱动）渲染 Trending 卡全量信息。
