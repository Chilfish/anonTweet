# 信息密度与界面冗余

> **适用范围：** 所有页面与业务组件。与 [README.md](./README.md) 的视觉规范同级，冲突时本文件的负向约束优先。
>
> 核心判断只有一句：**数据可以密，解释必须少。**

## 1. 铁律（负向约束）

1. **同一事实只写一次**。数字、标题、成员身份、入口不在同一屏出现第二遍。按钮里不再重复计数，卡片标题不重复列表标题。
2. **界面不写口径脚注**。统计范围、排序规则、加权方式、字段含义写进 `docs/` 或数据层，页面只留结果。需要脚注才能读懂的数字，先从这一屏删掉。
3. **标题本身是入口时不加「详情 →」「进入 X →」「阅读全文 →」**。一个区块最多一个动作。
4. **字段有值不等于要上屏**。先写这一屏回答的一个问题，只保留直接回答它的 3~5 项；其余进展开区、详情页或 API。
5. **description 只在 label 不自明时写**。禁止三种写法：复述 label（「过滤与博主无互动的评论」）、写实现细节（「经本站服务器中继」「build 时间」「HTML 结构」）、写使用建议（「默认最低即可」）。
6. **交互提示不常驻界面**。横屏提示、重试指引、语法教程放空态或错误态，不放页面头部。
7. **重复入口收进 `⋯` 菜单**。头部平铺按钮 ≤3 个，其余降级。
8. **不截断正文**。长文本换行；`truncate` 只用于确定的短标识（用户名、文件名、URL）。

## 2. 每屏预算

编写或评审页面时先填这三项，超出的内容必须有明确去处：

| 项目             | 上限 | 超出时               |
| ---------------- | ---- | -------------------- |
| 这一屏回答的问题 | 1 句 | 拆页                 |
| 首屏同权重区块   | 3 个 | 降级为次要样式或折叠 |
| 每区块动作按钮   | 1 个 | 进菜单               |
| 同屏重复事实     | 0 处 | 删除后出现的         |

首屏不滚动就能说出重点，否则视为未完成。

## 3. 验收动作

- **三秒测试**：三秒内能否说出这一屏是干什么的。
- **眯眼测试**：眯眼后能否看到一个主视觉，而不是一排等重的框。
- **删除测试**：逐个删掉 caption、脚注、副标题、入口文案，页面是否仍成立；成立就删。
- **净增行数**：只加不减的 UI 改动需要在 PR 里说明新增信息为什么必须同时在场。

## 4. 已知例外

- 截图路由（`plain.tsx` / `plain-ig.tsx`）：宽度由生产端控制，但必须保留 `overflow-x-auto` 兜底。
- 设置页：开关项可以带一句短说明，但同一区块内只允许一条，且不得是脚注形态。
- 数据表格、日志、调试面板：高密度合理，但层级靠位置与字重建立，不靠增加说明文字。

## 5. 提交前自查

- [ ] 页面没有需要解释口径的数字
- [ ] 同一个数字/入口只出现一次
- [ ] 没有「详情 →」「阅读全文 →」这类与链接重复的文案
- [ ] 没有 build 时间、commit hash、缓存层、CORS 这类实现细节
- [ ] 正文未被 `truncate` 截断
